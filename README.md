# Ministry Leave Management System (MERN + MySQL)

Leave Management System built with React, Vite, Tailwind CSS, Express (Node.js), and MySQL.

Run the backend test suite from the repository root with `npm --prefix backend test`.

## Local backend and Cloudflare Tunnel

Keep the backend running in one terminal:

```powershell
Set-Location D:\Ministry_leave_system-main\backend
npm start
```

It listens on `127.0.0.1:5000` by default. Check availability with
`Invoke-WebRequest http://127.0.0.1:5000/api/health`.

In another terminal, force Cloudflare Tunnel to use HTTP/2 to the Cloudflare
edge and connect it to the local origin:

```powershell
$env:TUNNEL_TRANSPORT_PROTOCOL = "http2"
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://127.0.0.1:5000
```

Quick Tunnel URLs can change when the tunnel is restarted. Set
`VITE_API_URL` in `Frontend/.env` to the current HTTPS tunnel URL before each
production build. A named Cloudflare Tunnel with a stable hostname is preferred
for deployments.

## Build and deploy Firebase Hosting

```powershell
Set-Location D:\Ministry_leave_system-main\Frontend
npm run build
firebase deploy --only hosting
```

Production API calls go through `src/api.js`; its production guard rejects an
unset or localhost `VITE_API_URL`.

## Email delivery and links

The backend sends password-reset and leave-workflow email through the shared
SMTP service. Configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`,
`FROM_NAME`, `FROM_EMAIL`, `REPLY_TO_EMAIL`, and `FRONTEND_URL` in
`backend/.env`. Use the provider's verified sender address for `FROM_EMAIL`;
for Gmail SMTP, authenticate with the matching Gmail or Google Workspace
mailbox and an app password where required. Do not put SMTP secrets in source
control. Production email links default to
`https://leave-7a9d6.web.app`; local development links default to
`http://localhost:5173` unless `FRONTEND_URL` is set.

Leave-action email buttons open the appropriate role-protected dashboard queue.
Recipients must sign in and confirm actions in the application; opening an
email link does not approve or reject a leave request. Reset links open the
existing `/reset-password` route and continue to use the backend's expiring,
single-use token validation.

Inbox placement cannot be guaranteed by application code. Spam filtering also
depends on sender reputation, message content, and SPF/DKIM/DMARC authentication;
check the full message headers and provider delivery logs when diagnosing a
specific message. For a custom sending domain, configure the exact SPF and DKIM
records generated by the SMTP/email provider, then publish a DMARC TXT record
at `_dmarc` (start with monitoring, for example `p=none`, and review reports
before enforcing a stricter policy). Maintain a single SPF record and merge
authorized senders into it rather than publishing multiple SPF records. A
personal `@gmail.com` sender does not have customer-managed DNS records; use
Google's authentication for that account or a verified custom domain if you
need domain-level DNS control.

## MySQL network access

The backend connects to MySQL through the loopback address. MySQL itself must
also be restricted to loopback (for example, `bind-address=127.0.0.1` in its
server configuration). If MySQL is listening on all interfaces, run this once
from an elevated PowerShell session to block inbound TCP port 3306:

```powershell
New-NetFirewallRule -DisplayName "Ministry Leave System - block inbound MySQL" -Direction Inbound -Protocol TCP -LocalPort 3306 -Action Block -Profile Any
```
